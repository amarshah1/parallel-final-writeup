\subsection{Leaf-only Equalities on Binary Nodes}

Our first set of benchmarks is parameterized by several parameters. $l$ denotes the number of leaves---i.e. the ``variables'' that appear within terms. $w$ denotes the \emph{width} of the benchmark: how many equalities are initially given before computing their congruence closure. The parameter $n$ denotes the total number of \emph{nodes}, which are non-leaf terms (e.g. function applications). The \emph{depth} $d$ denotes the depth of the terms, or how many nested function applications appear in the term. For example, the term $f(g(x))$ has depth 2, and the term $x$ (a single variable) has depth 0. The parameter $f$ denotes the number of function symbols. Finally, the parameter $p$ denotes the number of software threads.

We now describe the experiments. We fix $f = 16$; for all experiments, we fix the number of function symbols at 16. Additionally, the arity of each function symbol is 2; we only construct binary operators for these experiments. For one set of experiments, we stratify our workloads into different size classes, which are shown in Table~\ref{tab:workloads}.
